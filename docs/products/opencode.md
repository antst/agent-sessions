# OpenCode product facts

- OpenCode was pinned and exercised as native version `1.18.25`; the packaged `@opencode-ai/plugin` dependency was also `1.18.25`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencode/opencode.go:14`, `ff81565:integrations/opencode/package.json:29`]
- A managed headless product server is started as `opencode serve --hostname <loopback-host> --port <port> ...` in the requested working directory. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/server.go:84-126`]
- The server accepts HTTP Basic authentication from `OPENCODE_SERVER_USERNAME` and `OPENCODE_SERVER_PASSWORD`; the old integration generated a fresh 32-byte password. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/server.go:76-81`, `ff81565:internal/products/opencodefamily/server.go:121-130`]
- The verified server surface is HTTP plus SSE. Readiness probes unscoped `GET /doc` and requires `/session` and `/event`; the exact successful document fixture is `{"paths":{"/session":{},"/event":{}}}`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/server.go:128-143`, `ff81565:internal/products/opencodefamily/client_test.go:295-312`]
- Session-scoped HTTP routes carry `?directory=<absolute-cwd>`; `/doc` is deliberately unscoped. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:92-124`, `ff81565:internal/products/opencodefamily/client_test.go:38-51`, `ff81565:internal/products/opencodefamily/client_test.go:295-303`]
- Native session IDs have the form `ses_` followed by ASCII letters, digits, `_`, or `-`, with a 256-byte maximum. Native message and permission IDs use the same closed grammar with `msg_` and `per_`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:25-29`, `ff81565:internal/products/opencodefamily/client.go:70-90`, `ff81565:internal/products/opencodefamily/client.go:404-406`, `ff81565:internal/products/opencodefamily/client.go:682-685`]
- Fresh creation is `POST /session?directory=<cwd>` with JSON `{"title":"<title>","permission":[{"permission":"*","pattern":"*","action":"ask|allow"}]}`; the response must contain a valid `ses_*` ID. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:201-224`, `ff81565:internal/products/opencodefamily/client_test.go:54-99`]
- Exact resume is `GET /session/<ses_id>?directory=<cwd>` and succeeds only when the returned JSON repeats that ID, for example `{"id":"ses_exact","title":"renamed"}`. There is no latest-session fallback. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:227-239`, `ff81565:internal/products/opencodefamily/client_test.go:64-65`]
- Native retitle is `PATCH /session/<ses_id>?directory=<cwd>` with `{"title":"<title>"}`; success requires the response to repeat both ID and title. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:264-278`, `ff81565:internal/products/opencodefamily/client_test.go:66-67`]
- A turn is submitted to `POST /session/<ses_id>/prompt_async?directory=<cwd>`. The exact minimal JSON shape is `{"messageID":"msg_<deterministic-id>","noReply":false,"parts":[{"type":"text","text":"input"}]}`; optional `model`, `agent`, and `variant` members are native prompt controls. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:281-312`, `ff81565:internal/products/opencodefamily/client_test.go:68-75`]
- `prompt_async` acceptance is HTTP 204 with no response body. A deterministic `msg_` ID is derived before the request, so the accepted native message is known without parsing a response. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:84-90`, `ff81565:internal/products/opencodefamily/client.go:290-312`]
- The exact permission event fixture is `{"type":"permission.asked","properties":{"sessionID":"ses_exact","id":"per_exact"}}`; the exact idle event is `{"type":"session.idle","properties":{"sessionID":"ses_exact"}}`. Both arrive as SSE `data:` payloads from `/event?directory=<cwd>`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client_test.go:76-84`]
- Permission replies use `POST /session/<ses_id>/permissions/<per_id>?directory=<cwd>` with `{"response":"once|always|reject"}`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:682-696`]
- Product errors can arrive as `{"type":"session.error","properties":{"sessionID":"ses_exact","error":{"name":"UnknownError","data":{"message":"Model not found: native/product-model"}}}}`; the nested product message is the useful diagnostic. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client_test.go:277-292`]
- Terminality is reconciled against the ordered transcript from `GET /session/<ses_id>/message`: the admitted user `msg_*` must appear before a completed assistant message. An SSE idle event alone is advisory. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:384-435`, `ff81565:internal/products/opencodefamily/client.go:637-679`]
- The exact successful transcript fixture is `[{"info":{"id":"<msg_id>","sessionID":"ses_exact","role":"user"},"parts":[{"type":"text","text":"input"}]},{"info":{"id":"msg_assistant","sessionID":"ses_exact","role":"assistant","parentID":"<msg_id>","finish":"stop","time":{"completed":123}},"parts":[{"type":"text","text":"done"}]}]`. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client_test.go:85-86`]
- `finish:"tool-calls"`, an empty finish, and OpenCode's `finish:"unknown"` are nonterminal; a later completed assistant message with another finish supplies the result. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:377-381`, `ff81565:internal/products/opencodefamily/client_test.go:363-393`]
- Interrupt is `POST /session/<ses_id>/abort?directory=<cwd>` with `{}`. The JSON response must be exactly the boolean `true`; `false` is a native rejection. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:320-336`, `ff81565:internal/products/opencodefamily/client_test.go:192-229`]
- Native deletion is `DELETE /session/<ses_id>?directory=<cwd>`; `true` is success and 404 is already converged. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/client.go:339-357`, `ff81565:internal/products/opencodefamily/client_test.go:171-189`]
- Default permission maps to one native wildcard rule `{"permission":"*","pattern":"*","action":"ask"}`; bypass maps to the same rule with `"action":"allow"`; other shared values are unsupported. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/permission.go:8-20`, `ff81565:internal/products/opencode/permission_test.go:11-22`]
- The plugin receives identity from native `session.created` and `session.updated` event objects, accepting IDs from `properties.info.id`, `properties.session.id`, or `properties.sessionID`; `session.deleted` removes presence. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/agent-sessions.mjs:78-89`, `ff81565:integrations/opencode/agent-sessions.mjs:159-191`]
- A requested fresh title is written with `client.session.update({path:{id},query:{directory},body:{title}})` and must be echoed by the SDK before it is reported. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/agent-sessions.mjs:163-185`]
- The plugin's `shell.env` hook obtains the exact native ID from `input.sessionID`; the old integration exported that value for child tools only after validating it as `ses_*`. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/agent-sessions.mjs:194-205`]
- The interactive inbound path is product-native SDK work: the plugin finds the latest product-confirmed user `agent` and `model`, then calls `session.promptAsync` with `{"messageID":"msg_<id>","agent":"<agent>","model":{"providerID":"<provider>","modelID":"<model>"},"parts":[{"type":"text","text":"<delivery>"}]}` and requires HTTP 204. This starts a prompt; it is not an append-only injection primitive. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/agent-sessions.mjs:39-48`, `ff81565:integrations/opencode/agent-sessions.mjs:126-156`]
- No native running-turn injection or idle append primitive was verified in the 0.4.0 code. Its Go lane explicitly returned unsupported steer, while its plugin delivery started `promptAsync`; a new wrapper must not relabel that as injection or queueing without new product evidence. [OpenCode 1.18.25; source: `ff81565:internal/products/opencodefamily/lane.go:259-261`, `ff81565:integrations/opencode/agent-sessions.mjs:126-156`]
- Agent Sessions tool ingress was an in-process OpenCode plugin tool named `agent_sessions`, not an MCP transport. The tool context supplies `sessionID`, `messageID`, and an abort signal. This proves the plugin path and does not prove that OpenCode lacks other MCP support. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/agent-sessions.mjs:207-223`, `ff81565:integrations/opencode/README.md:3-10`]
- The plugin must be installed in exactly one supported location; loading both global and project copies duplicates the adapter and tool. [OpenCode plugin 1.18.25; source: `ff81565:integrations/opencode/README.md:3-5`]
- UNVERIFIED before a new wrapper: the installed OpenCode/SDK pair on `umka-dev1`, its v2 capability probe, and the app-ready boundary. The signed design records a deployed SDK `1.2.10` versus CLI `1.18.28` and requires this probe before hello; the pinned 1.18.25 sources cannot establish that newer combination. [OpenCode version pending host probe; source: `91fdcb3:docs/designs/UNIVERSAL-SESSION-PROTOCOL.md:1580-1585`, `91fdcb3:docs/designs/UNIVERSAL-SESSION-PROTOCOL.md:1751`]
- UNVERIFIED before a new wrapper: any session-level append or confirmed active-turn injection primitive. The only captured inbound path starts `promptAsync`, so it cannot truthfully implement lane-idle queueing or active injection. [OpenCode version pending host probe; source: `ff81565:internal/products/opencodefamily/lane.go:259-261`, `ff81565:integrations/opencode/agent-sessions.mjs:126-156`, `91fdcb3:docs/designs/UNIVERSAL-SESSION-PROTOCOL.md:1584`]
- UNVERIFIED before a new wrapper: native MCP transport/configuration support. The verified integration is the in-process plugin API; the planned wrapper likewise keeps the JS kit and tool inside that plugin and does not require a product MCP transport. [OpenCode version pending host probe; source: `ff81565:integrations/opencode/agent-sessions.mjs:207-223`, `91fdcb3:docs/designs/UNIVERSAL-SESSION-PROTOCOL.md:1583`]
