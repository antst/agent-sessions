# Agent Sessions v0.4.0

Agent Sessions gives native AI coding products one shared peer-messaging and
worker-lane layer while each product continues to own its session identity,
title, history, authentication, prompting, interruption, resume, and archive
behavior.

Version 0.4.0 includes nine product adapters: Codex, Claude Code, Grok Build,
Qwen Code, OpenCode, Kilo Code, Pi, Oh My Pi, and DeepSeek Harness. Eight have
interactive peer wrappers; all nine have worker-lane support. The release uses
one per-user daemon and an optional independent federation hub.

Linux is the runtime-proven release platform. The release also contains
precompiled Linux and macOS archives for x86-64 and arm64. Verify the selected
archive and release-evidence document against `SHA256SUMS` before installing.

## Native products and protocol

Peers can discover and message other live sessions directly, by explicit
multicast, or by group. Lanes start, resume, steer, wait for, interrupt, and
archive product-native worker sessions through the same daemon. Product data
and credentials remain product-owned.

The version 1 native presence and lane wire contract is published at
`docs/PROTOCOL.md`. Any product, TUI, or feed can implement it; dashi is the
first external implementer.

## npm packages

The release publishes six scoped npm packages:

| Product surface | Package | Product-native installation form |
| --- | --- | --- |
| OpenCode | `@agent-sessions/opencode@0.4.0` | `opencode plugin @agent-sessions/opencode@0.4.0 --global` |
| Kilo Code | `@agent-sessions/kilo@0.4.0` | `kilo plugin @agent-sessions/kilo@0.4.0 --global` |
| Pi | `@agent-sessions/pi@0.4.0` | `pi install npm:@agent-sessions/pi@0.4.0` |
| Oh My Pi | `@agent-sessions/omp@0.4.0` | `omp plugin install @agent-sessions/omp@0.4.0` |
| DeepSeek Harness communications | `@agent-sessions/dsh-comms@0.4.0` | installed together with the lane package by the command below |
| DeepSeek Harness lane | `@agent-sessions/dsh-lane@0.4.0` | installed together with the communications package by the command below |

The host installer uses DSH's native profile command with the two exact release
archives:

```sh
dsh plugin --profile agent-sessions add --offline \
  agent-sessions-dsh-comms-0.4.0.tgz \
  agent-sessions-dsh-lane-0.4.0.tgz
```

OpenCode and Kilo expose no native remove subcommand at the validated baseline;
remove only the exact package entry from the product's native global `plugin`
array. Pi uses `pi remove npm:@agent-sessions/pi`; OMP uses
`omp plugin uninstall @agent-sessions/omp`. Do not delete product-owned caches.

## macOS status

macOS is **not validated in v0.4.0**. Compatibility and the macOS release lane
are restored in v0.4.1. The known v0.4.0 Mac validation baselines are:

- two stale Darwin-only bridge tests refer to six symbols removed from the
  production package, so the Darwin bridge test package does not compile;
- npm's JSON for `publish --dry-run` does not portably expose the same top-level
  `result.integrity` field, although the separately computed package-archive
  SHA-512 SRI remains available; and
- stock macOS Bash 3.2 can enter the installer rollback twice through the
  `ERR` trap in the transaction fixture.

These are tracked for v0.4.1. The Darwin archives in this release are build
artifacts, not macOS runtime-acceptance evidence.

## Installation

Install the host from a source checkout with `make install` and follow
`docs/INSTALL.md`. Installation never approves product trust, authentication,
or permission prompts. After installing a product into a new executable
directory, start a fresh shell and rerun the Agent Sessions installer so the
user daemon captures the same `PATH`.
